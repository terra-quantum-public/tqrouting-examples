# TQrouting Examples

Jupyter notebooks showing how to solve vehicle routing problems with **TQrouting**,
the Python SDK for Terra Quantum's vehicle routing solver.

TQrouting computes optimized routes for a fleet of vehicles serving a set of
customers: capacities (one- or two-dimensional), time windows, driver shifts,
route duration and distance limits, pickup and delivery, multi-trip reloads,
heterogeneous fleets, multiple depots, prize-collecting, and any combination
of these. Distance matrices come from your own data, from OSRM, or from Google
Maps.

## Tutorials

Short notebooks that walk through the SDK feature by feature, in this order:

| Notebook | What's inside |
|---|---|
| [quickstart.ipynb](tutorials/quickstart.ipynb) | **Start here.** Build a small capacitated VRP, solve it, plot the routes. |
| [constraints.ipynb](tutorials/constraints.ipynb) | Everything that decides which solutions are *allowed*: time windows, capacities (1-D and 2-D), route limits, shifts, pickup & delivery, multi-trip reloads, heterogeneous fleets, multiple depots. |
| [objectives.ipynb](tutorials/objectives.ipynb) | What the solver *minimizes*: duration/distance trade-off, prize-collecting, fixed vehicle costs, waiting-time pricing, soft constraints. |
| [workflow.ipynb](tutorials/workflow.ipynb) | The practical plumbing: JSON round-trips, time formats, schedules and departure times, infeasibility and warnings. |
| [real_world_osrm.ipynb](tutorials/real_world_osrm.ipynb) | GPS coordinates and road-network matrices via OSRM (public demo server, or a local Docker server for a 500-customer instance), map plots. |

Each notebook is self-contained: run the setup cell at the top, then jump to
any section. Outputs are committed, so you can read the results on GitHub
without running anything.

## Getting started

You need Python 3.11–3.14 on Linux (x86-64), macOS 14 or newer (Apple
Silicon), or Windows (x86-64), and a TQrouting license key.

```bash
git clone https://github.com/terra-quantum-public/tqrouting-examples.git
cd tqrouting-examples
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
export TQROUTING_LICENSE_KEY="..."
# Windows: $env:TQROUTING_LICENSE_KEY = "..."
jupyter lab tutorials/quickstart.ipynb
```

TQrouting is published on Terra Quantum's package index, and `requirements.txt`
already points pip there. To install the SDK by hand:

```bash
pip install tqrouting --extra-index-url https://europe-python.pkg.dev/bright-primacy-486519-b9/tq-public/simple
```

**Linux:** the bundled solver needs `libcurl4` and `libgomp1`. Desktop
distributions have them; minimal container images may need
`apt-get install -y libcurl4 libgomp1` (Debian/Ubuntu) or
`dnf install -y libcurl libgomp` (RHEL/Fedora).

**License key:** every solve verifies the key online, so the machine needs
internet access.

A valid license key is required to use the library. To request access, please
follow the application process here: [the TQrouting access request form].

**Docker** is only needed for the local-OSRM section of `tutorials/real_world_osrm.ipynb`.

## Data

`tutorials/data/` holds synthetic instances only: four plane-coordinate
instances generated by a script that ships with them, and one 500-customer
instance with real GPS coordinates around Ingolstadt for the OSRM notebook.
Details in [tutorials/data/README.md](tutorials/data/README.md).

## Running a notebook without opening Jupyter

```bash
jupyter nbconvert --to notebook --execute tutorials/quickstart.ipynb --output-dir output
```

The executed copy lands in `output/`. The Docker section of
`tutorials/real_world_osrm.ipynb` needs a running Docker daemon and downloads a map
extract on first use.
